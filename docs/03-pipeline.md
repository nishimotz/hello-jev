# 03. 判断を組み合わせる

## 出力を次の入力にする

判断専用モデルは、次の一手を決めない。
組み合わせるのはコードの仕事。

```
入力 (item)
  ↓
判断A (choice) → 確信度で分岐
  ├ 高確信 & カテゴリX → 処理X（自動）
  ├ 高確信 & カテゴリY → 処理Y（自動）
  └ 低確信            → 人間レビューキュー
```

判断A の結果が、次にどの処理を通るかを決める。
各段に確信度のゲートを置くのが高信頼化の要点。

## 確信度で3段階に分ける

```python
from common import AUTO_THRESHOLD, REVIEW_THRESHOLD

def route(confidence: float) -> str:
    if confidence >= AUTO_THRESHOLD:   # 例: 0.90
        return "auto"
    if confidence >= REVIEW_THRESHOLD: # 例: 0.60
        return "review"
    return "fallback"
```

- **auto** — 機械が確定してよい
- **review** — 人間が確認する
- **fallback** — 判断が定まらない。既定の処理に倒す

閾値は**自分のデータで較正するもの**。ここに挙げた値は例示。

## 較正の考え方

閾値を決めるには、正解付きのサンプルで測る。

1. サンプルを Jev に通し、確率と正解を記録する
2. 確率の帯ごとに正答率を見る
   - 0.9 以上なら本当に 9 割以上正しいか
   - 0.6〜0.9 はどうか
3. 正答率が許容できる帯を自動化し、残りを人間に回す

確率が高いほど正答率も高い、という関係が崩れていたら、
criteria の書き方か state の設計を見直す。

## 並列に問う

Jev は1回の呼び出しで複数の問いを同時に評価できる。

```python
questions = {
    "is_urgent": {...},
    "department": {...},
    "severity": {...},
}
```

1件ずつ3回呼ぶより、3問を1回にまとめる方が速く安い。
ただし、**前の判断結果が後の問いに必要な場合は分ける**。
依存関係があるなら段階を分け、無いならまとめる。

## アンチパターン

- **確信度を捨てる** — `choice` の値だけ使って confidence を見ない。これでは汎用 LLM との差が出ない
- **1つの判断に全部やらせる** — 「カテゴリと緊急度と深刻度をまとめて」と1問にすると、criteria が曖昧になる。分けて並列に問う
- **閾値を固定して測らない** — 自分のデータで較正しないと、自動化しすぎるか、人間に回しすぎるかになる
