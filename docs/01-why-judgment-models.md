# 01. なぜ判断専用モデルか

## 汎用 LLM に判断を頼むと何が起きるか

汎用 LLM に「このメールは緊急か」と聞くと、文章で返ってくる。
JSON 形式を指示すれば、だいたいは従う。だが次の問題が残る。

- **遅い**。トークンを1つずつ生成するので、判断1つに秒単位かかる
- **高い**。出力トークンは入力の数倍の課金になる
- **型が崩れる**。指示に反して説明文を混ぜたり、定義にない値を返すことがある
- **確信度が無い**。`"urgent"` と返っても、どれくらい確信しているか分からない

判断に迷っている場合でも、同じ扱いになる。これが高信頼システムを作るうえで致命的になる。

## 判断専用モデルという発想

Jev は判断だけを行う。出力は次の3型に限られる。

- `noul` — yes である確率
- `choice` — 定義済み選択肢から1つ。各選択肢の確率と confidence
- `score` — 順序付きレベル上のスコア。各レベルの確率と confidence

定義した形式の値しか返さないので、**形式エラーは仕組みの上で起きない**。
そして確率が返るので、**確信度で処理を分けられる**。

## 設計思想: 制御フローはコードが持つ

判断専用モデルは、次の一手を決めない。決めるのはコード。

```
モデルの仕事: 状態を受け取り、型付きの判断を確信度付きで返す
コードの仕事: 判断と確信度を読み、次に何をするか決める
```

この分離が、高信頼システムの土台になる。
プロンプトに挙動を書くのではなく、判断の型と閾値をコードで定義する。
