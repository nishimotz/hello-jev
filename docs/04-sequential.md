# 04. 時系列を扱う

## 判断専用モデルは履歴を持たない

Jev は1回の呼び出しごとに独立している。会話の記憶は無い。
だから「直前の文脈」が必要なら、**コードが state に入れる**。

```python
state = {
    "current": "またログインできません。",
    "recent_decisions": [
        {"summary": "請求金額の問い合わせ", "department": "billing"},
        {"summary": "パスワード再設定の依頼", "department": "account"},
    ],
}
```

この設計には利点がある。

- **何を文脈として渡すかをコードが制御できる。** 渡しすぎれば精度が落ち、渡さなさすぎれば文脈が消える
- **再現できる。** 同じ state なら同じ判断になる。デバッグしやすい
- **プライバシーを制御できる。** 履歴の要約だけを渡し、原文は渡さない、といった設計ができる

## 窓の設計

直近何件を渡すか（窓のサイズ）は、判断の性質で変わる。

- 短い窓（1〜3件）— 直前の話題だけを引き継ぐ
- 長い窓（5〜10件）— 流れや傾向を見る
- 窓の内容も選ぶ — 全件ではなく「関連しそうなもの」だけ渡す

**窓のサイズは正解が先に決まらない。** 実データで効果を測って決める。
教材では仮の値（3〜5件）を置き、検証の題材にする。

## 文脈を入れると何が変わるか

例: 問い合わせの分類。

- 文脈なし — 「ログインできない」→ account と分類
- 文脈あり（直近が請求の話）— 「またログインできません」が請求経緯の続きかもしれない、と判断が変わりうる

文脈が効くかどうかは、**測らないと分からない**。
「直近の判断結果を入れた場合と入れない場合で、正答率が変わるか」を比較する。

## 逐次処理の組み立て

```
items = [...]  # 処理対象の列
recent = []

for item in items:
    state = {"current": item, "recent_decisions": recent[-N:]}
    answers = evaluate(state, QUESTIONS)
    record(answers)                 # 判断を記録する
    recent.append(summarize(item, answers))  # 要約だけを窓に残す
```

- 原文をそのまま窓に溜めない。**要約に落とす**
- 窓は固定長にする（`recent[-N:]`）。無制限に伸ばさない
- 各判断を記録する。後で較正に使う

## リアルタイム処理の場合

判断が速いことを活かす使い方。

- 判断1回が短時間で返るので、人間の知覚より速く意思決定できる
- レイテンシの予算を決める。間に合わない場合は判断を落とす、遅いフォールバックに回す、を選ぶ
- 窓を短くする。リアルタイムでは文脈より即時性が優先される

**判断専用モデルは、判断を落とす設計がしやすい。**
確率が返るので「確信度が低ければこの回は判断しない」を自然に書ける。
